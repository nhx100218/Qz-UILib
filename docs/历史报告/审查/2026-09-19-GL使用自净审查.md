# GL 使用自净审查（Qz-UILib）

> 审查对象：`src/main/java` 全部直接触碰 OpenGL 的生产代码（48 文件 / 1182 处 GL 符号引用，GL11 直连 667 行）。
> 方式：Lead 亲自读码闭环 + 独立深读分支交叉验证，**每条结论均经 Lead 回读代码复核**。只读审查，未改任何代码。
> 前置事实：本仓**不使用** MC `GlStateManager` 承担状态管理（生产 0 处引用），全部直连 LWJGL；"自净"完全由自建 Guard/Scope 承担，无宿主兜底。
> 编号：`N*` 非自净-缺陷 ｜ `I*` 非自净-有意合理 ｜ `G*` 自净良好 ｜ `R*` 待复核。

## 〇、结论摘要

| 类别 | 数量 |
|---|---|
| **非自净-缺陷** | **23** |
| **非自净-有意合理** | 20 |
| **自净良好** | 24 |
| **待复核 / 待真机** | 18 |

三条最要紧的判断：

1. **入口不对称**：HUD 有整帧围栏，**屏幕（GuiScreen）入口没有**（N1）——不是漏一两项状态，而是两个入口的自净契约不对等。
2. **"硬编码终值"而非"读回原值"反复出现**：纹理绑定写 0（N2）、colorMask/depthMask 写 true（N4）、`fillRect` 强制开 TEXTURE_2D（N6）——判据 1 的直接违反；多数被外层 `glPushAttrib(GL_ALL_ATTRIB_BITS)` 偶然兜住（见 R1），但**依赖"外层恰好 push 了"不是自净**。
3. **异常路径是系统性弱项**：恢复链顺序执行、前项失败中断后续（N9/N15/N16），4 处"保护域建立/拆除不在同一 try"（N3/N5/N7/N10），1 处"压栈后未登记/未回滚"（N15）。本仓已有正确样板（`UiRenderTarget.restoreStep`、`drawUncachedHostImage`、`HudGlStateGuard.appendFailure`），属**风格不统一**而非能力不足。

## 一、判据

1. 状态写入有 save/restore 配对，且恢复**进入时读回的真实原值**（硬编码默认值不算自净）。
2. 异常/提前 return 路径同样必须恢复（try/finally 或等价）。
3. 资源创建有释放路径，不以 GC/上下文销毁为唯一依赖（除明确说明的兜底）。
4. 绑定（texture/framebuffer/buffer/program）用后恢复原绑定。
5. 允许"由外层/宿主负责"，但**必须在注释里写明契约**；否则记为缺陷。

## 三、非自净-缺陷（23 条）

### N1 屏幕入口没有 GL 状态围栏【结构级，最高优先】

`ui/screen/McScreenBridge.java:237-303`；`beginMainUiFrame` 做 `glViewport`(`UiHostRenderSupport.java:153`) 并调 `prepareMainUiRenderState()`(:157→:164-172：关 depth/cull/alpha/lighting、开 blend、color=1)，而 `MainFrameScope.close()`(:122-131) **只弹两个矩阵栈并恢复 matrix mode**：

```java
public void close() {                       // UiHostRenderSupport.java:122-131
    GL11.glMatrixMode(GL11.GL_MODELVIEW);   GL11.glPopMatrix();
    GL11.glMatrixMode(GL11.GL_PROJECTION);  GL11.glPopMatrix();
    GL11.glMatrixMode(previousMatrixMode);
}
```

对照 HUD 的 `HudGlStateGuard`（恢复 viewport:131/305、enable 位:306-312、colorMask/depthMask/color）。后果：屏幕帧后 GL 停在 UI 语义上，靠 MC `setupOverlayRendering` 每帧重设掩盖，对同帧后续渲染的其它模组不成立，且无契约注释。建议抽出公共帧围栏包住 `drawScreen`，`MainFrameScope` 至少补 viewport 快照。

### N2 纹理绑定恢复成硬编码 0，未读回原值（4 处）

- `ui/render/UiBackdropFilterRenderer.java:259`（每次 backdrop 渲染必执行；同文件已读回 program:194 与 activeTexture:195，**唯独漏 `GL_TEXTURE_BINDING_2D`**）
- `ui/render/UiRenderTarget.java:179/193`（`compositeToCurrentFramebuffer`，经 `PaintContextCompositor.java:192/298`、`UiRenderContext.java:998`、`UiHostRenderSupport.java:277` 每帧可达）、`:142/156`（`drawToScreen`，无调用点，死代码中的潜在缺陷）、`:230/249`（5 参重载）
- 后果：回贴/玻璃后当前活动单元 2D 绑定被清 0；沿用"上次绑定纹理"续画的下游会画成无纹理。
- 修复：照 `ui/render/UiMainLayerSnapshotService.java:495-496/607-612` 的做法读回后原值回绑——**正确写法在同包内**。定级前提见 **R1**。

### N3 圆角剪裁掩码重建无 try/finally：colorMask 可被异常悬挂

`ui/render/ClipStack.java:391-415`：`glClear`(395) → `colorMask(false×4)`(396) → `depthMask(false)`(397) → 几何绘制(404-406) → 409-414 才恢复，中间 3 个可抛点且无 finally。任一 `cornerRadius>0` 的 clip 在此窗口抛异常 → **colorMask 全关被悬挂，本帧后续 UI 静默不写色（整块消失）**；帧边界也不恢复 colorMask。附带：全包 `glBegin/glEnd`=9/9 配对，但**只有 `UiContextGlHelpers.java:62-73` 把 `glEnd` 放进 finally**。

### N4 剪裁宿主基线未捕获 colorMask/depthMask，栈空恢复硬编码 true

`ui/render/ClipStack.java:541-542` 写 `colorMask(true×4)`/`depthMask(true)`，而捕获点 `captureCurrentHostBaseline:297-325` **只读 scissor+stencil** → 非原值恢复。宿主若关着掩码进来，剪裁栈回空后会被打开。类 javadoc(:28-29) 只声明 stencil 范围，故不算"有意"。

### N5 文本绘制路径矩阵 push/pop 无 try/finally

`ui/render/UiRenderContext.java:691-700`、`:725-729`：push → translate/scale → **第三方字体调用**(694-699) → pop，无 finally。异常时 MODELVIEW 多一层未弹 → 后续 UI 整体错位，累积可致栈溢出（`MainFrameScope.close` 只弹 1 层）。与本仓自身规范（`GlStateScope.java:18-19`"异常路径由其 finally 恢复"）矛盾。

### N6 基元绘制路径无保护、无契约（每帧必跑）

`ui/render/UiRenderContext.java:375-391`（`fillRect`）：`glEnable(BLEND)`、改 blendFuncSeparate、`glDisable(TEXTURE_2D)`…`glEnable(TEXTURE_2D)`(388)、color 白(389)；出口只"归一"不自恢复，javadoc 未提 GL。关键：帧入口 `prepareMainUiRenderState` **不设 TEXTURE_2D**，故 :388 是往外扩而非收敛。HUD 侧由 Guard 兜住，屏幕侧并入 N1。

### N7 背景滤镜：保护域建立在 try 之外

### N8 着色器失败路径泄漏 + 进程级 program 无上下文失效钩子

### N22 `GlStateScope` 丢失 task 异常（诊断信息）

- **源码级审查**：headless/CI 观测不到真机 GL 状态守恒，所有结论都是"源码路径闭合"级判定，最终仍需真机组合验证（§六）。

- 主动**撤回或降级 6 条**初判（避免误报）：
