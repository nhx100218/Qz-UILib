# 指令入口

Qz UILib 的客户端指令是 `/qzuilib`。**可用子命令随运行环境分两档**：发布产物只带玩家通道，
开发设施只在开发环境存在。

| 环境 | 可用子命令 |
| --- | --- |
| 发布产物（玩家装的 jar） | `modernconfig`、`chatmd on\|off\|status` |
| 开发环境（build/classes） | 上述两个 + `test`（scene 测试场地）+ `glass`（磨玻璃实验室） |

分档来自打包边界：`internal.devtools` **整包**不进发布产物（`build.gradle.kts` 的
`verifyDevToolsNotPackaged` 门禁逐个打开产物断言），开发设施子命令的实现随包一起消失。
`ClientProxy#registerQzUiLibCommand()` 按「开发环境 + 类存在」双重探测择一注册——同一环境
只注册一个同名命令，发布产物回退到只含玩家通道的命令（`client.command.QzUiLibClientCommand`）。

发布产物内的子命令同样属 internal 调试设施，不构成对外公共 API 承诺；本文只描述诊断入口约束，
业务 UI 打开方式以 `../03-宿主集成/Minecraft界面入口.md` 为准。

## 不会注入的默认入口

为避免与宿主自有界面冲突，本库不会向原版界面或全局热键注入入口：

- 不在原版背包页插入 `背包UI` 按钮。
- 不绑定全局热键打开或关闭诊断菜单。

## 指令入口

```text
发布产物：/qzuilib <modernconfig|chatmd on|off|status>
开发环境：/qzuilib <test|glass|modernconfig|chatmd on|off|status>
```

命令语义：

- `/qzuilib test`（**仅开发环境**）打开 scene 测试场地（`TestPlaygroundEntry.open()`）——游戏内
  演示/验收文本输入、浮层与响应式能力的调试入口。
- `/qzuilib glass`（**仅开发环境**）打开磨玻璃实验室（`GlassLabEntry.open()`）——backdrop-filter
  磨玻璃观感与渲染路径验收。
- `/qzuilib modernconfig` 打开新架构配置页（`ModernConfigEntry.open()`）——uilib 作为新架构配置页
  首个真实使用方的调试入口。玩家侧的等价入口是 Mod 列表里的配置按钮（`ModConfigGui`）。
- `/qzuilib chatmd on|off|status` 聊天 3.0 接管开关与状态诊断；**只改本次运行态、不写配置**，
  持久真源是配置项 `general.chatFrame`。`off` 是接管异常时的逃生舱。

## 时序约束

- 聊天命令执行结束后，聊天界面仍会继续关闭当前 `GuiScreen`。
- 因此客户端命令不能在 `processCommand(...)` 中直接 `displayGuiScreen(...)`；
  开屏逻辑委托 `ModernConfigEntry.open()`（内部走延后开屏路径）。

## 验收

- 普通打开原版背包时不出现 `背包UI` 测试按钮。
- 按右 Shift 不打开诊断菜单。
- 发布产物里 `/qzuilib test` 与 `/qzuilib glass` 被拒绝（回显用法），补全里也不出现它们——
  这两个子命令的实现随 `internal.devtools` 排除，放行会走到缺类的开屏路径。
- 开发环境 `/qzuilib test` 能打开测试场地，分段导航切换页面正常，文本输入框可聚焦编辑、
  右键菜单/对话框/Toast 可用。
- `/qzuilib modernconfig` 能打开新架构配置页，字段编辑与保存反馈正常。
